# 学习笔记 · 目录说明

> 这里是主人的学习笔记。**每条笔记都是资产** —— 面试时能讲出来的东西，90% 来自这里。
> 笔记用 Markdown 写，随代码一起 commit，GitHub 上就是你的「学习轨迹」。

---

## 命名规则

```
notes/
├── 01-环境和第一次调用.md      ← 第 1 周
├── 02-流式输出与错误重试.md    ← 第 2 周
├── 03-embedding与向量检索.md   ← 第 3 周
└── ...
```

**规则**：`序号-主题.md`。序号跟 `行动方案.md` 里的周次对齐，方便回看。

---

## 每篇笔记的固定结构（照这个写，别自由发挥）

```markdown
# 标题

## 一、这周我做了什么
（3-5 行，干了什么、跑通了什么）

## 二、我搞懂了什么（★核心）
（这是面试能讲的部分。用「一句话结论 + 为什么 + 例子」的格式写）

## 三、踩过的坑
（报错原文 + 原因 + 怎么修的。★面试官特别爱问这个）

## 四、还没弄懂的
（老实写。下次回来解决，或者去问人）

## 五、数据记录
（token 消耗、耗时、准确率……★能写数字就写数字）
```

**为什么这么要求**：`项目实战.md` 里那条追问链自查表的逻辑是一样的 ——
**面试官追的是「为什么」和「你怎么知道的」，不是「你做了什么」。**

---

## 本鱼的提醒

- 笔记**不需要写给谁看**，但请假设「三个月后的你自己」会读到它 —— 那时候你早忘了细节
- **踩坑部分最重要**，别嫌丢人不写。能讲清楚一个坑的人，比只报喜的人可信十倍
- 每周至少 1 篇。第 1 周那篇已经给你起好头了，见下方目录
