### base_url 可以换（接口兼容）

**结论**：base_url 相当于各个大模型的**门牌号 / 地址**，改掉它就能切换到另一个模型。

**为什么**：国内主流平台都实现了同一套 OpenAI 兼容协议，所以代码骨架不用动。

**边界在哪**：换平台除了 `base_url`，还要改 **API Key** 和 **model 名字**；
而且这套兼容**只到「普通对话」层面** —— 以下功能各家会分叉：

- **工具调用（function calling）**：特别是流式返回时 `tool_call` 的 ID 累积策略，各家不同
- **多模态（图片/音频）**：完全各搞各的
- 结构化输出（JSON Schema 约束）、缓存计费：支持度参差不齐

> 本鱼批注：✅ 答对了，而且 A3 你直接点中「工具调用 + 多模态」这两个最典型的分叉点。

### temperature

**结论**：控制**随机性**。值越大越放飞，值越小越收敛。

**为什么**：它在采样时把 token 的概率分布「变平」或「变尖」。

**我实测观察到**：
- `temperature=0` 时主答案概率极高，但**偶尔会抖一次**（本鱼跑两轮 6 次：第一轮 4 种结果，第二轮 2 种结果）
- `temperature=1.1` 时输出明显更发散
- **重点**：`temperature=0` 只说明**确定性较高**，**不能保证完全不变**

> 本鱼批注：✅ 概念全对。**但要补一个更锐利的点**：
> 「两次一样」**不能**证明确定（样本太少）；而「两次不一样」**1 次就能证伪**。
> **证伪便宜、证实昂贵** —— 这个不对称是做实验最重要的直觉。
>
> ⚠️ 另外 B2 你答成了「temperature 越大随机度越高」，本鱼问的是**你的 6 次跑出了几种结果** ——

### token 与成本

**结论**：输入和输出**单价不同，输出更贵**（通常是输入的 3-4 倍）。

**为什么成本意识重要**：62% 的企业把「运营成本预测失败」列为 AI 落地最大的扩展障碍。

**成本的杠杆在哪**：
- **减少输入**：优化上下文 → 这一边你答到了（RAG 检索精度直接影响成本）
- **减少输出**：限制 `max_tokens`、让模型说短话 → 另一边别忘了
- **缓存命中**：同样的前缀会命中服务端缓存，**便宜很多**
  → `usage.prompt_cache_hit_tokens` 就是看这个的（本鱼实测字段：`hit=0 / miss=30`）

> 本鱼批注：C2 你只答了「优化上下文」，**漏了输出侧**；C3 答对了「成本变高」，
> 但漏了最关键的一句：**检索越多 → 噪声越多 → 准确率可能反而下降**，
> 也就是「**成本涨了、效果没涨**」——这才是 RAG 要优化的核心矛盾（第 6-7 周的主线）。

**① 为什么「两次一样」不能证明 temperature=0 就确定？**

| 坑 | 报错原文 | 原因 | 怎么修的 |
| --- | --- | --- | --- |
| 中文乱码 | `��������ģ��` | Windows PowerShell 默认按 **GBK** 解码 Python 的输出，而 Python 写的是 UTF-8 | 脚本开头加 `sys.stdout.reconfigure(encoding="utf-8")`；跑的时候再设 `PYTHONIOENCODING=utf-8` |

| ⚠️ `.venv` 差点被提交 | `git status` 里冒出几万个 `.venv/...` 文件 | `.gitignore` 被整份覆盖，**python 规则全丢了**，`.venv/` 不再被忽略 | `git reset` 取消暂存 → 把规则补回 → `git check-ignore -v .env/.venv/.idea` 逐条验证 |
| 中文文件名显示成 `\344\275\240` | —— | git 默认对非 ASCII 路径做转义 | `git config --global core.quotepath false` |
| ⚠️ 成本估算高估 4 倍 | 脚本算出 0.000680 元，实际约 0.00018 元 | 本鱼用了**记忆里的旧价目**，没去核官方文档（单价会调） | 查 [官方价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 重算 → 并在代码注释里写死**价格来源 + 日期** |
| ⚠️ `deepseek-chat` 是旧别名 | 服务端返回 `model='deepseek-flash'` | 官方现名是 `deepseek-flash`，别名随时可能下线 | 配置项化模型名；用正式名时注意 **thinking 模式默认开启**（更慢更贵） |
| ⚠️ `seed` 传了不报错但不生效 | 无明显报错，输出照样变 | 官方参数表**根本没有 `seed`**，SDK 静默透传、服务端静默忽略 | 加参数前查文档；加完设计对照实验**验证生效**（见 `补充-查文档挖出的三个坑.md`） |

### 成本感受（按闲时价重算）

- 单次对话约花费：**0.00009** 元
- 1 元钱大约能跑：**约 1.1 万次**
- 每天 1000 次请求的应用，一个月（30 天）成本约：**约 2.7 元**
- 每天 10 万次的应用，一个月约 **270 元** ← 到量级就不可忽略了

> ★ 这一条是**面试可以主动讲**的：说明你有规模化成本的意识。
> ★ 更值钱的是**价格来源要写清日期**——单价会变（2026-05 DeepSeek 还宣布过永久降价），
> 不写来源的成本估算，过一个月就可能是错的。

### ★ 本鱼的估算错在哪（这个比数字重要）

- **错因**：本鱼用了记忆里的旧价目（输入 ¥2 / 输出 ¥8 每百万），没有去核官网
- **后果**：高估约 4 倍 —— 如果是给老板报预算，方向虽然保守（高估比低估安全），
  但**结论会变**：本来「便宜到可以忽略」，被算成「要盯一下」
- **教训**：**成本是硬数字，必须查文档、写来源、标日期**；凭记忆算 ≈ 编数据
